# 预售专用流程停用

按用户要求，2026-11-06注释停用：

- 库存流自动补充预售候选（mergeStockPlans仅返回销售目录列表）。
- 前端预售提示、预订徽标、预订任务按钮与preorder参数发送。
- 后端新任务保存preorder标记及预售专用入队例外。
- 购买前PreorderReady销售目录等待。
- 预订专用硬件匹配分支及WaitingForCatalog队列分支。

本区库存已有的Eco型号不会再被要求先建立预订任务，可以直接进入普通抢购流程。历史preorder=true任务也按普通流程处理，无需删库迁移。跨区、非Eco、账户、普通配置校验保留；自定义planCode仍可使用。

数据库兼容字段、枚举和未被生产链路调用的旧辅助函数保留；原逻辑主要以注释保留，方便回溯。停用前的提取快照仅在本地 artifacts/ 保留，不纳入 Git；当前生效源码以仓库为准。

验证：新测试对照旧preorder=true与普通任务，确认目录未收录或目录故障不触发销售目录等待；真实请求止于mock购物车，不实际下单。新增前端测试确认不再自动发现预售候选。现有预售测试按当前停用行为更新。

停用不等于OVH一定接受订单，最终仍由实际库存和购物车接口决定。

最终验证：npm run verify 全部通过（TypeScript、生产构建、25项前端单测、全量后端测试、工具隔离测试与路由登记验证）。预热测试补齐共享HTTP客户端拦截，针对该测试连续3次通过；未修改生产预热逻辑。验证日志属于本地运行产物，不纳入 Git。

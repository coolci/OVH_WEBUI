# 服务器列表内置新增配置自动下单

按 2026-11-07 确认的规则，功能**默认开启**，由后端 Supervisor 驱动。关闭网页不会停止；服务器列表里的功能开关才控制启停。主动关闭会持久化，重启保持关闭。

首次运行（或关闭后重新开启），先绑定当时的默认账户及其 endpoint/销售子公司，独立直拉官方销售目录建立基线。第一次目录获取成功只记录已有配置，不下单。没有账户、地区配置错误、目录异常时不会开始下单。默认账户后来变更不会悄悄切换执行账户；要换账户需关闭再开启。

之后目标每 2 秒完成上一轮后再检查目录；网络/上游错误退避，最长 60 秒。按 planCode + 一套 addon 选项识别新增配置，官方 exclusive/mandatory 规则控制组合展开。价格、文案、字段排序、已有配置单纯恢复库存不会触发。已见配置下架后重新出现不重复触发。已有配置新增机房也创建该机型/配置/机房的独立任务；机房下架后重现不重复创建。

每个 planCode × 硬件/网络配置 × 机房各有一个独立任务，每个组合成功建单 1 台后永久停止自身；一个机房成功不影响其他机房。实际目标单数为每个新增机型下的各配置可用机房数之和。最多 100 个任务并发执行，同一组合持久化认领后不允许重复进入；无货重试本机房，确定性失败停止该组合，结账结果不确定时该组合转入后台自动核对，确认前不重复提交。固定 AutoPay=false。并发结账失败时不采用仅按机型模糊匹配近期订单的对账方式，避免把其他配置或机房的订单错误认领为成功。

开关、基线、待处理任务和完成记录存储在独立 `catalog_watch` 表，不读写 ServerCache 或 CatalogService，不修改服务器列表的 120 秒刷新配置。普通服务重启恢复已有基线及未提交任务；如果上次中断时正处于下单中，转为“结果待核对”，不自动再发一单。关闭后重新开启会建立新基线，关闭期间已经存在的配置不会被回补购买。历史成功和未决记录不会被清除；每次切换开关会重置本轮计数，旧轮次结果不计入新轮次。

关闭开关取消尚未提交的尝试。已经发出的结账请求会先完成结果确认，不能撤回已经在 OVH 创建的订单。出现不确定结账结果时，页面显示“待核对”，后台按原账户、原购物车或已保存的订单编号自动查单。确认成功后写入抢购历史并走成功通知流程；确认未提交结账且仍属于启用中的当前轮次时恢复尝试。上游查询失败、404、空结果或无法准确关联订单时持续核对，不推断未建单。关闭开关后仍可核对已提交请求，但不会恢复旧轮次购买。详见 [自动查单规则](catalog-watch-reconciliation-2026-11-07.md)。

页面显示：开关、绑定账户、基线时间、已识别配置数量、最近检查、错误，以及本轮待尝试/已成功/待核对三项计数。订单详情统一在抢购历史展示，服务器列表不展示订单记录列表。接口 GET/PUT `/api/catalog-watch` 使用现有 API 鉴权；PUT 仅接收 enabled，不提供自动付款或购买数量设置。

已存在的独立 Python 脚本不由集成功能启动，也未实际运行；不要同时启动它的 execute 模式，两个系统之间没有共享去重记录。

回归覆盖默认开启、首次不下单、账户绑定、重新开启基线、每配置每机房独立任务、100 并发上限、关闭中途取消、关闭后结账结果保留、重启去重、保存失败禁止提交、原 120 秒缓存隔离、API 布尔输入、前端计数、自动查单和通知去重。测试均使用模拟接口，不需要真实账户或真实购买。

配置范围：硬件、带宽、vRack 等机器选项；可选的 `application-license` / `distribution-license`（Windows、SQL、cPanel 等软件许可）不作为自动新增配置，不枚举这些许可的叠加组合。若目录要求必选软件许可则停止该次自动解析并报告。

验证结果：生产构建、33 项前端测试、后端全量测试、工具回归和两份接口清单校验通过；最终目录解析和任务生命周期改动另做定向回归。官方 IE 目录只读结构样本包含 99 个机型，过滤可选软件许可后成功解析 10944 套硬件/网络配置。当前环境 CGO_ENABLED=0，未运行 Go race detector；并发互斥、关闭中途取消和关闭后结账结果保留由显式并发测试覆盖。

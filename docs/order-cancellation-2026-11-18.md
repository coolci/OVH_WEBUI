# 2026-11-18 自动付款停用与购买历史取消订单

本次仅修改 `OVH_WEBUI`。参考 `OVH_Rebuild/docs/功能需求.md` F-003 的“放弃未付款的订单”“撤回与退款”，没有修改参考项目，也没有向真实账户下单、付款或撤单。

## 自动付款

- 原前端控件、状态及提交字段、自动付款通知分支和结账参数赋值以注释保留。
- 当前独服与 VPS 的结账请求固定发送 `autoPayWithPreferredPaymentMethod=false`。
- 独服购买入口会忽略旧任务中的 `AutoPay=true`，快速下单新任务固定关闭；旧数据库字段和 API 字段保留兼容。
- 下单后需手动付款。账户页原有的显式手动付款功能保留。

## 购买历史操作

桌面表格和手机卡片上的“取消订单”会先读取实时 OVH 订单信息，不会在打开窗口时提交任何资金操作。

| 订单情况 | 操作 | 结果 |
| --- | --- | --- |
| 未付款，未过期且没有在途付款 | 确认放弃订单 | 本地持久保存 `abandonedAt`，阻止本系统付款，等待 OVH 到期作废；不向 OVH 提交撤回，不会自动重新抢购 |
| 已放弃，OVH 确认仍未付款且付款期限未到 | 撤销放弃 | 清除本地放弃标记，恢复手动付款能力 |
| 已付款，支持撤回且 OVH 撤回期限未到 | 选择原因、确认含税金额后申请撤单退款 | 提交整张订单的 `POST /me/order/{id}/retraction`，最终取消和退款以 OVH 为准 |
| 美区、无撤回权、已过期、已取消或状态无法确认 | 显示具体说明 | 不提交撤单 |
| 已有付款或撤单未决请求 | 显示核对提示 | 不重复提交 |

“已放弃·待作废”是本地状态，区别于 OVH 的“取消中 / 已取消”。外部在 OVH 网页主动付款不受本系统拦截；后续状态刷新仍以 OVH 为准。

## 接口与持久化

- `GET /api/purchase-history/:id/cancellation?account=<accountId>`：只读核对；返回 `mode`（`abandon / retract / unavailable`）、`canRestore`、说明、实时含税金额/币种及截止时间。
- `POST` 同路径：必须传 `confirm:true` 和 `mode`（`abandon / restore / retract`）。`retract` 还必须传实时确认的 `amount`、`currency` 和合法 `reason`，`comment` 可选且最多 1000 字。
- 必须同时匹配历史行 ID 和下单账户，不能回退到默认账户。提交时重新向 OVH 核对，金额、状态或资格变化即拒绝并要求重新打开窗口。
- 操作记录独立保存于现有 SQLite `kv` 的 `order-cancellation:<accountId>:<orderId>`，不新增表或列。历史列表读取时合并记录，避免异步整表保存历史覆盖操作结果；清空历史不会删除防重复登记。
- 放弃和手动付款的登记共用写事务，保证并发时不能同时生效。付款预检及最终原子登记都拦截已放弃订单。
- 撤单先持久写入 `sending` 再发送，成功为 `submitted`；明确拒绝为 `failed`，允许用户重新核对后确认。超时、连接错误、5xx、408/409/429 为 `uncertain`，不自动重试；重启后 `sending / submitted / uncertain` 仍禁止重复提交。用户需在 OVH 核对未决结果。
- 已交付订单若有在途撤单，状态刷新会继续跟踪，避免旧的 `delivered` 终态规则阻止取消结果更新。

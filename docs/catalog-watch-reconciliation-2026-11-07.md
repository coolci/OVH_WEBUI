# 自动查单与本轮计数（0.4.13）

- 自动下单在结账 POST 前同步保存原购物车、账户、任务以及提交标记；保存失败禁止提交。
- 结账超时、响应无法解析、缺少订单编号时保留原购物车，进入后台只读核对，不创建新购物车重试。
- 成功响应的订单编号也同步保存。核对优先使用成功历史或已保存的订单编号，否则读取原购物车及其 checkout 的订单编号，并用原账户读取对应 `/me/order/{id}` 进行验证。
- 未验证购物车、404、限流、空结果及预览返回的零订单编号均不构成“未建单”证据。OVH 官方 schema 仅说明 GET checkout 为价格/合同预览，没有保证它始终返回已创建订单。无法取得准确关联时持续自动核对，不通过时间阈值强行恢复购买。
- 可证明尚未提交结账的中断任务自动恢复；明确的业务拒绝仍走原来的重试/不支持机房处理。旧轮次关闭后只核对、不恢复购买。
- 核对失败后至少间隔 15 秒再次检查；查询有超时，其他机房任务继续执行。旧版缺失购物车证据的任务只能通过已保存成功历史确认，不能猜测归属。
- 确认成功使用统一历史与通知流程；已有成功历史不重复发送。没有补发旧订单 Telegram 通知。
- 切换开关持久化新的统计轮次。三项数字仅统计当前轮次；历史成功、防重记录及旧轮次未决请求均保留。旧请求晚到的结果不计入新轮次。
- 新配置/机房独立购买、100 并发上限、固定关闭自动付款和列表 120 秒刷新保持不变。

测试覆盖：响应丢失后重启并查单、仅一次 checkout/历史/通知、只读查询、未验证购物车、404、429、预览零编号、错误关联编号、明确未提交恢复、旧轮次不恢复、切换及重启后计数归零但防重保留。

API 依据：https://eu.api.ovh.com/1.0/order.json 与 https://eu.api.ovh.com/1.0/me.json（2026-11-07 读取）。测试拦截所有 HTTP，不产生真实订单或真实 Telegram 消息。
